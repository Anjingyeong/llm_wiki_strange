# 뷰스컴퍼니 LLM 사내 자동화 개발자 — 면접 직전 압축본

> **목표:** 많이 외우지 않는다. 아래 **한 캐릭터 + 회사 3줄 + JD 3축 + 핵심 8문항**만 말할 수 있으면 된다.
>
> **내 캐릭터:** AI로 빠르게 만들되, 실제 로그·테스트·사용 결과로 검증하고 계속 고치는 주니어 자동화 개발자.

---

## 0. 면접장 들어가기 전 이것만 본다

### 한 줄 자기소개

> **AI를 실제 서비스와 업무에 연결하고, 빠르게 만든 뒤 검증하며 개선하는 개발자 안진경입니다.**

### JD를 면접용으로 기억할 3축

공고 문구를 통째로 외우지 말고 아래 세 방향으로 답변을 통일한다.

1. **빠르게 만든다** — 완벽한 설계만 오래 고민하기보다 작은 결과물을 먼저 만든다.
2. **빠르게 배운다** — 처음 쓰는 기술도 필요한 범위부터 학습해 실제 기능으로 검증한다.
3. **실제 일을 줄인다** — LLM 사용 자체가 목적이 아니라 현업의 반복 업무와 병목을 줄인다.

### 내 경험을 3축에 붙이면

| JD 축 | 내 경험 | 면접에서 할 말 |
| --- | --- | --- |
| 빠르게 만든다 | 개인 웹서비스·JK·LLM Wiki를 직접 구현/배포 | “작게 만들고 실제 동작부터 확인합니다.” |
| 빠르게 배운다 | AI → Spring Boot → LLM/RAG/배포까지 확장 | “필요한 기술을 기능 단위로 배우고 바로 적용합니다.” |
| 실제 일을 줄인다 | JK, LLM Wiki, 자동화 관심 | “기술보다 사람이 반복하는 흐름부터 봅니다.” |

### 답이 막히면 이 구조

> **현업 흐름 확인 → 반복/병목 찾기 → 작은 MVP → 로그·테스트·사용자 확인 → 효과 있으면 확장**

# 1. 뷰스컴퍼니는 3줄만 기억

### 회사 이해

- 과거 **D2C·자사몰·퍼포먼스 마케팅 경험**을 기반으로 사업을 확장해왔다.
- 현재는 **뷰티 콘텐츠·크리에이터 IP/팬덤·마케팅·커머스**를 연결하는 성격이 강하다.
- 최근에는 **글로벌 K-뷰티, 북미/유럽 인플루언서, TikTok Live, 크리에이터 콘텐츠** 영역도 확장하고 있다.

### 개발자 입장에서 해석

> 콘텐츠·크리에이터·광고·글로벌 운영이 늘수록 **리서치, 데이터 정리, 분류, 번역, 보고서 작성처럼 반복되는 정보 업무**도 커질 수 있다. 그래서 LLM 사내 자동화가 실제 생산성으로 연결될 여지가 큰 회사라고 이해한다.

**주의:** 내부 프로세스를 직접 본 것은 아니므로 “회사에서 지금 이 업무를 하고 있다”고 단정하지 않는다. 자동화 아이디어는 **회사 사업 구조를 보고 한 가설**이라고 말한다.

### 회사 설명 20초

> “뷰스컴퍼니는 과거 D2C와 퍼포먼스 마케팅 경험에서 출발해 현재는 뷰티 콘텐츠와 크리에이터, 커머스를 연결하고 글로벌 K-뷰티까지 확장하고 있다고 이해했습니다. 사업 채널이 많아질수록 리서치나 데이터 정리, 콘텐츠 운영처럼 반복되는 정보 업무도 늘 수 있어서 LLM 사내 자동화 역할이 실제 생산성으로 이어질 수 있는 회사라고 생각했습니다.”

# 2. 1분 자기소개

> “안녕하십니까. **AI를 실제 서비스와 업무에 연결하는 개발자 안진경입니다.**
>
> 의공학을 전공하며 인공지능과 딥러닝을 공부했고, 이후 개발 역량을 보완하기 위해 SK쉴더스 지능형 애플리케이션 개발 과정에서 Spring Boot 기반 스마트 안전관제 시스템을 개발했습니다.
>
> 최근에는 LLM과 하네스 엔지니어링에 관심을 가지고 AI를 활용해 개발부터 테스트·배포까지 효율화하는 개인 프로젝트와 문서 기반 LLM Wiki를 직접 만들어보고 있습니다.
>
> 저는 **AI로 빠르게 만들되, 로그와 테스트로 결과를 검증하며 개선하는 개발자**입니다. 이러한 경험과 개발 방식이 이번 LLM 사내 자동화 직무와 잘 맞는다고 생각해 지원했습니다.”

### 기억 키워드

`AI 전공 → 개발 보완 → 스마트 관제 → LLM/자동화 → 빠르게 만들고 검증`

문장을 통째로 암기하지 않는다. 위 다섯 덩어리만 기억한다.

# 3. 핵심 예상질문 8개

## Q1. 왜 뷰스컴퍼니인가요?

**기억:** `사업 확장 → 반복 정보업무 → 내 방식과 맞음`

> “특정 뷰티 기술 때문이라기보다 **LLM을 실제 회사 업무에 붙이는 포지션**이라는 점이 가장 끌렸습니다. 뷰스컴퍼니가 콘텐츠와 크리에이터, 글로벌 영역까지 사업을 넓히고 있어서 리서치나 데이터 정리처럼 반복되는 업무를 자동화했을 때 효과를 직접 확인하기 좋은 환경이라고 생각했습니다. 저도 빠르게 만들고 실제 사용 결과로 개선하는 방식으로 프로젝트를 해왔기 때문에 잘 맞는다고 생각했습니다.”

---

## Q2. 왜 일반 개발이 아니라 LLM 사내 자동화인가요?

**기억:** `모델보다 연결 → 사람이 하던 일 감소`

> “AI 모델 자체를 연구하는 것도 경험했지만, 저는 결과가 실제 사용자에게 전달되고 **사람이 하던 일이 줄어드는 순간**에 더 재미를 느꼈습니다. 그래서 한 기술만 깊게 파는 것보다 Python, API, LLM, 웹을 필요한 만큼 연결해 현업 문제를 해결하는 자동화 역할에 관심이 커졌습니다.”

---

## Q3. 입사하면 무엇부터 자동화하고 싶나요?

**기억:** `기술부터 X → 현업 관찰 → 작은 MVP`

> “바로 LLM 서비스를 만들기보다 먼저 각 팀의 반복 업무를 보겠습니다. 예를 들어 크리에이터 후보 조사나 캠페인 자료 취합처럼 **빈도가 높고 규칙이 비교적 명확한 업무가 실제로 있는지** 확인하고 싶습니다. 그중 실패 위험이 낮고 효과를 측정하기 쉬운 하나를 작은 MVP로 만든 뒤 절감 시간과 오류, 실제 사용률을 보고 확장하겠습니다.”

### 자동화 아이디어 하나만 기억

`크리에이터/캠페인 자료 수집 → 정리·분류 → 요약/보고서 초안 → 사람 검수`

이건 **회사 내부 업무가 확인됐다는 뜻이 아니라 면접용 가설**이다.

---

## Q4. 바이브 코딩을 잘한다는 게 뭐라고 생각하나요?

**기억:** `AI에게 많이 시키기 X → 빠른 구현 + 사람이 기준 설정`

> “저는 바이브 코딩을 AI에게 코드를 많이 시키는 것이라고 생각하지 않습니다. 요구사항을 작은 단위로 나누고 AI를 이용해 구현 속도를 높인 뒤, 사람이 테스트와 로그를 보고 결과를 검증하는 방식이라고 생각합니다. **무엇을 만들지, 어디까지 만들지, 언제 완료라고 볼지는 사람이 판단해야 한다**고 생각합니다.”

---

## Q5. AI가 만든 코드를 어떻게 믿나요?

**기억:** `코드 확인 → 실행 → 로그/테스트 → 위험도 따라 검증 강도`

> “그대로 믿지는 않습니다. 중요한 데이터 흐름은 직접 확인하고 실제 실행 결과와 로그, 테스트가 기대한 대로 나오는지 봅니다. 인증이나 데이터 손실, 배포처럼 영향이 큰 부분은 더 보수적으로 검증하고 단순 UI처럼 위험이 낮은 부분은 빠르게 확인합니다. 다른 AI의 리뷰는 보조 수단이고 최종 기준은 실제 동작과 테스트입니다.”

---

## Q6. LLM Wiki를 왜 만들었나요? 회사 업무와 무슨 관련이 있나요?

**기억:** `문서 흩어짐 → 찾기 어려움 → 구조화/검색 → 사내지식으로 연결`

> “프로젝트를 진행하면서 코드와 실험 결과, 판단 근거가 여러 곳에 흩어져 다시 맥락을 찾는 데 시간이 많이 들었습니다. 그래서 문서를 구조화하고 검색해서 필요한 근거를 빠르게 찾는 LLM Wiki를 만들었습니다. 회사에서도 업무 매뉴얼이나 캠페인 자료처럼 흩어진 정보가 많다면 검색·요약이나 후속 자동화에 연결할 수 있다고 생각합니다. 핵심은 웹페이지를 만든 것이 아니라 **문서를 LLM이 활용할 수 있는 형태로 정리하고 검색 품질을 확인해본 경험**입니다.”

### 꼬리: RAG가 뭐예요?

> “질문할 때 관련 문서를 먼저 검색하고 그 문맥을 LLM에 같이 제공해 답을 만드는 방식입니다. 자주 바뀌고 출처가 중요한 사내 문서에 적합하다고 생각합니다.”

---

## Q7. 왜 안진경 씨를 뽑아야 하나요?

**기억:** `AI 경험 + 서비스 연결 + 빠른 학습/검증`

> “AI를 공부만 한 것이 아니라 백엔드와 서비스까지 연결해본 경험이 있고, 최근에는 LLM을 실제 개발·검색·자동화 흐름에 붙여보고 있습니다. 아직 주니어라 모든 기술을 안다고 말할 수는 없지만 **필요한 기술을 빠르게 배우고 작은 결과물을 만든 뒤 로그와 테스트로 고치는 방식**에는 익숙합니다. 이번 직무가 원하는 업무 방식과 제 강점이 잘 맞는다고 생각합니다.”

---

## Q8. 뷰티 업계 경험이 없는데 괜찮나요?

**기억:** `모른다고 인정 → 사용자/업무 흐름부터 학습`

> “뷰티 도메인 경험이 많다고 말씀드릴 수는 없습니다. 대신 자동화는 개발자가 도메인을 추측해서 만드는 것보다 실제 사용자의 업무 흐름을 배우는 게 먼저라고 생각합니다. 현업이 어떤 데이터를 보고 어떤 기준으로 판단하는지 먼저 배우고, 제가 가진 AI와 개발 역량으로 반복되는 부분부터 줄이겠습니다. 새로운 기술이나 도메인을 필요한 범위부터 빠르게 익혀 적용해온 경험도 있습니다.”

# 4. 프로젝트는 4개 답변만 방어

## 1) 스마트 안전관제 — 문제 해결

**기억:** `문제 재현 → 같은 조건 비교 → 수치로 검증`

> Tracking ID가 자주 바뀌는 문제를 같은 테스트 영상으로 반복 재현하고 트래킹·동기화 조건을 조정했다. 핵심은 “좋아진 것 같다”가 아니라 **동일 조건에서 전후를 비교했다는 점**이다.

면접에서 수치를 말할 경우 반드시 **측정 조건까지 함께** 말한다.

## 2) LLM Wiki — 직무 연결

**기억:** `흩어진 지식 → 검색 → 근거 있는 답`

> 웹 자체보다 문서를 구조화하고, 검색 결과가 실제 질문에서 잘 나오는지를 확인한 경험이 핵심이다.

## 3) JK/하네스 — 직무 연결

**기억:** `AI 답변 → 실제 실행 → 승인/로그/실패 복구`

> “AI가 코드를 써주는 것”에서 끝나지 않고 실행환경과 연결했을 때 생기는 권한, 승인, 결과 확인 문제에 관심을 갖고 만든 프로젝트라고 설명한다.

**주의:** “완전 자율 에이전트” 같은 과장은 하지 않는다. 내가 직접 정한 것은 **요구사항, 자동화 범위, 권한 경계, 완료 기준, 테스트·수정 방향**이라고 말한다.

## 4) 새로운 기술 학습 — SongSong 등 개인 프로젝트

**기억:** `필요한 범위 학습 → 바로 구현 → 실제 사용하며 수정`

> 처음부터 기술 전체를 공부한 뒤 시작하기보다 필요한 기능을 작은 범위로 만들고 공식 문서와 AI를 활용해 배우며 배포 후 실제 사용 문제를 수정한 경험으로 연결한다.

# 5. 자동화 설계 질문은 이 하나로 통일

어떤 시나리오가 나와도 아래 순서로 생각한다.

1. **현재 사람이 하는 순서**를 먼저 본다.
2. 입력·출력·사람의 판단 지점을 나눈다.
3. 반복 빈도, 소요 시간, 오류 위험을 확인한다.
4. 규칙으로 되는 것은 일반 코드/스크립트를 쓴다.
5. 비정형 텍스트의 분류·요약·작성처럼 필요한 부분에만 LLM을 쓴다.
6. 처음에는 사람 검수를 남긴 작은 MVP로 만든다.
7. **시간 절감 / 오류율 / 사용률 / 비용**을 보고 확장한다.

### “왜 Agent 안 쓰나요?”가 나오면

> “여러 도구를 스스로 선택하고 여러 단계를 판단해야 할 때 Agent가 유용할 수 있지만, 정해진 순서로 처리되는 업무라면 일반 워크플로우가 더 예측 가능하고 유지보수하기 쉽다고 생각합니다. 저는 Agent부터 정하기보다 업무 복잡도에 맞게 가장 단순한 방법부터 선택하겠습니다.”

### “LLM이 필요 없는 업무면?”

> “규칙이 명확하면 Python이나 기존 SaaS가 더 단순하고 안정적일 수 있습니다. **자동화 개발자의 목표는 LLM 사용이 아니라 일을 줄이는 것**이라고 생각합니다.”

# 6. 인성 질문은 새 답변 만들지 않는다

| 질문 | 가져올 경험 | 한 줄 결론 |
| --- | --- | --- |
| 강점 | 빠른 개인 프로젝트 + 관제 검증 | **빠르게 만들고 수치/로그로 확인한다** |
| 단점 | 초기에 범위를 넓게 잡음 | **우선순위와 종료조건을 먼저 잡는 쪽으로 보완 중** |
| 실패/아쉬움 | 기술을 많이 시도해 범위가 커진 경험 | **좋은 기술보다 필요한 기술을 고르는 게 중요** |
| 협업/리더십 | 5인 팀장 | **내가 많이 하는 것보다 팀이 계속 움직이게 하는 게 중요** |
| 새 기술 | 개인 웹서비스/LLM 도구 | **필요한 범위부터 배우고 작은 기능으로 검증** |
